# 体系背景：工作单位扩大、开发接续与验证闭环

2026-10-11 用户确认背景论述；2026-10-21 用户采纳愿景主线，明确与现成编码 Agent 的分工边界，并补充非专业用户可用、体系自治理与用户无需维护内部机制的愿景。本文拥有体系的愿景主线、易用与自治理目标、定位边界、趋势判断、因果关系与介绍开场；架构与执行合同仍由原文档拥有。这是发展方向与设计动机，不是已经实现的能力或已证明的普遍效果。

## 愿景概括：五个关键词及解释

2026-10-21 用户确认采用以下五点，作为当前理解和沟通项目愿景的概括；完整论述与定位边界保留在下文。

1. **堪当重任**：可靠承接规模更大、复杂度更高、开放性更强、持续时间更长的开发委托。
2. **自主交付**：自主完成调查、设计、执行、验证和纠偏，直到交付满意的真实结果。
3. **普适易用**：非专业人员无需学习内部机制，也能表达目标、委托工作、使用结果。
4. **自我治理**：体系自主维护、修复和恢复，无需用户持续照料。
5. **持续进化**：吸收模型与工具的进步，通过真实项目探索、效果验证和经验沉淀，不断改进自身能力。

## 愿景主线：持续扩大人能够放心委托给 AI 的工作范围

让人能够把越来越复杂、越来越开放、持续时间越来越长的开发目标交给 AI，由体系自主推进，直到交付满意的真实结果。人决定目标、关键取舍和授权边界；体系逐步承担为完成目标所需的调查、设计、实现、验证、接续与改进，减少人亲自拆解、催促、检查和纠偏的负担。

在这条主线上，补充普适易用与体系自治理的愿景：包括非专业人员在内的用户，无需学习和维护体系内部机制，也能表达目标、委托工作、使用结果；体系逐步承担自身治理、维护和异常恢复。可委托的工作范围持续扩大，同时让使用门槛与用户维护负担持续降低，两方面共同推进。

委托范围可以沿着“一项修改 → 一个完整功能 → 一项大型交付 → 一个产品 → 一项长期研发职责”扩大。这是探索方向，不是固定实施阶段，也不意味着当前已具备整条路径的能力。当前仓库是起点：模型进步提高理解、创造和解决问题的能力；宿主 Harness 支持执行、运行与接续；上层方法和最佳实践积累可复用的经验；真实项目不断暴露新的能力边界，推动下一轮改进。这些力量共同服务于可放心委托的工作范围扩大。

新增机制都应回答：它让我们能够放心交出去的工作，具体扩大了什么？效果同时看委托范围与不确定性、结果质量、人工推动与纠偏、交付时间和成本；不能用自主行动次数、规则数量或文档数量替代。

## 易用与自治理：非专业用户无需学习和维护内部机制

面向所有有开发诉求的人，包括没有软件工程和 AI 工具专业知识的用户。目标体验是：用自己的语言表达想法，在必要时说明偏好、做关键选择并授权，直接使用和评价结果。使用体系不以学习工作流、Skills、Harness、资料结构或规则维护为前提；把内部步骤包装成按钮后仍要求用户充当项目经理或维护人员，也没有达到这个愿景。

体系需要逐步形成两个相互支撑的闭环：

- **交付闭环**：围绕用户目标完成理解、探索、设计、执行、验证和必要返工，交付可用结果。
- **体系治理闭环**：发现接入、配置、状态、资料或方法中的问题，在授权内维护和修复，验证修复效果并恢复推进；通过实践改进方法，并清理过时或无收益的机制。

治理和维护的负担由体系内部消化，目标是让用户无需持续照料这一层。异常出现时，体系尽量自主诊断和恢复；确需用户参与时，用用户能理解的方式说明影响及所需决定。人保留目标、关键取舍、授权与停止权；自治理沿用既有边界，不要求重建宿主已有的运行或恢复能力。

易用程度要用非专业用户的真实委托检验：未经内部流程培训能否开始并拿到结果，需要多少专业操作或人工救援，中断后能否继续，以及是否反复要求用户学习或维护内部机制。交付与治理两类闭环都需用真实运行证明；减少可见步骤不能替代内部问题得到解决。

## 定位边界：建设在现成编码 Agent 之上的开发体系

擎天利用 Codex、Claude Code 等现成编码 Agent 及其 Harness，建设更上一层的完整委托、工程交付与实践积累能力。我们不会重做 Codex 或 Claude Code，也不以自建通用编码 Agent、替代其客户端或重复实现其底层执行循环为方向。

| 分工 | 擎天的建设选择 |
| --- | --- |
| 编码执行、工具调用、会话与运行环境等基础能力 | 优先复用宿主已有能力；具体支持范围以实际工具与接入验证为准 |
| 完整目标、验收依据、跨任务组织与开发接续 | 在宿主之上组织工作流、方法、项目资料和证据，推进整体交付 |
| 真实项目探索、经验沉淀与效果评估 | 用真实委托暴露缺口，验证并复用有效方法，淘汰无收益或过时做法 |
| 为上述目标必需的工具与衔接机制 | 先核对宿主原生能力，只补有证据的上层缺口，并明确与宿主的责任边界 |

涉及调度、状态、恢复、协作或验证的设想，都先检查现成工具能否满足需要，再决定适配或补充。模型与宿主能力提升后，重新评估原有补丁是否仍有必要。具体接入能力以[当前实现事实](current-state.md)与实际验证为准。

## 核心判断

随着模型和 Harness 能力增强，Agent 能承担的工作单位有机会从局部修改扩大到完整需求、大型交付与持续迭代。**工作单位扩大是核心背景；跨执行者、跨会话和跨环境接续是由此产生的工程要求，验证闭环则让更完整的执行能力转化为可靠交付。**

## 因果结构

```text
模型能力与 Harness 能力增强
└── Agent 能承担的工作单位扩大
    ├── 从局部修改 → 完整需求 → 大型交付与持续迭代
    │
    ├── 推导一：工程工作需要脱离单个会话，支持接续与协同
    │   ├── 时间维度：任务更长，需要暂停、中断和恢复
    │   ├── 人员维度：多人接手、分工与协作
    │   ├── 会话维度：跨会话接续、多会话协同
    │   └── 环境维度：换设备、换地点、换执行环境
    │
    └── 推导二：完整工程闭环变得可行，也更值得建设
        ├── Agent 能推进更完整的工程过程
        ├── 验证提供反馈：结果与目标之间还差什么？
        ├── 未通过：定位缺口，返回对应环节继续修正
        └── 整体完成条件满足：退出循环、完成交付
```

## 接续与协同：工程状态独立于当前会话

工作单位扩大后，任务生命周期可能超出单个会话、一个人的工作时段和一个设备的使用周期。暂停与交接是正常使用需求，多人和多会话协同也需要共享有效依据。因此，项目资料须保存目标与约定、设计依据、执行状态、验证证据及下一动作，让接手者核对现场后从已有有效成果继续。

执行者和执行环境可切换是这一背景推导出的要求，不把“执行者变得可切换”本身当成独立的趋势前提。合上电脑、换地点或换设备的例子需要区分两类保障：资料与状态支持暂停后接续，执行本身持续运行则依赖宿主及实际运行环境。多人或多会话协同还需要处理并发修改、权限和状态归属；保存文档不自动完成这些能力。具体接续定义见[开发连续性](system-architecture.md#开发连续性可交接可接续)。

## 验证闭环：反馈与退出依据

Agent 有机会推进完整工程过程，因此建设从目标到交付的执行闭环更有价值。**验证是闭环的关键反馈机制，也是判断何时继续、何时退出的依据。** 它将实际行为与有效目标、验收标准对照，发现差距并将问题送回理解、设计、实现或验证等适用环节。

“验证通过”在整体交付层面指必要结果得到有效证据支持，并满足适用 Review、交付与复盘等完成条件，不是某个局部测试通过。存在真实阻塞时记录未完成项与所缺条件，不用盲目重试代替推进；阶段门、返工及整体完成仍沿现有 Lifecycle。证据角色见[工程产物与证据](artifact-traceability.md)，流程组织见[三层架构](system-architecture.md#总体模型三层架构)。

## 介绍开场

> 随着模型和 Harness 能力增强，我判断 Agent 能承担的工作单位会持续扩大，从局部修改走向完整需求、大型交付和持续迭代。
>
> 这会带来两个工程要求。首先，任务越来越长，中断、交接和协同会成为正常情况，所以开发状态需要脱离当前会话，支持跨人、跨会话和跨环境接续。其次，Agent 有机会推进完整工程过程，因此值得建立从目标到交付的执行闭环，其中验证负责发现差距、驱动修正，并提供退出循环的依据。
>
> 擎天就是围绕这两个要求组织的：让工程工作能够持续接续，也能够依据验证结果推进到完整交付。

## 已出现的信号与推断边界

OpenAI 的工程实践讨论了将人的职责转向环境设计、意图表达和反馈回路；Anthropic 的长任务研究讨论了跨会话开发与结构化产物交接。这些是一手实践信号，不据此宣称所有团队都已采用相同方式，也不宣称擎天是独有或普遍有效的方案。[OpenAI：Harness engineering](https://openai.com/index/harness-engineering/)、[Anthropic：Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

背景中的能力趋势与工程要求用于解释为何探索这套体系；已实现能力、实践证据和效果限制分别以[当前事实](current-state.md)、架构及具体测评为准。
