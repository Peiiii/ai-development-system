# 接入指南

擎天把可复用的工作流、Skills 和项目资料约定带进已有项目，依托现成编码 Agent 执行开发工作。接入后，照常向 AI 提出目标，由它读取适用的方法和项目资料。

## 准备条件

准备一个项目仓库，以及能够联网、使用终端并读写该项目文件的 AI 编码助手。当前原生目录布局面向 Codex；其它工具的规则与 Skills 自动发现方式，需要实际验证。

## 把指令交给 AI

复制下面的指令，发送给当前项目中的 AI：

```text
请读取 https://ai-dev.nextclaw.io/SKILL.md，按照其中的步骤，把擎天接入当前项目。先检查现有规则和工作区改动，预览安装差异，完成后运行检查并告诉我改了什么。
```

入口包含当前安装归档、校验信息与操作方式。AI 应先查看现有规则和工作区，再进行预览、安装与核对。已有同名文件或受管文件发生冲突时，安装器会停止，避免覆盖已有内容。

## 确认接入结果

让 AI 说明新增或修改了哪些文件、检查是否通过、还有什么冲突。接入会保留项目自己的产品事实、授权与专属规则；安装共享方法不等于把其它项目的知识复制过来。

接入后直接提出实际任务即可，例如：“调查这个错误并修复，验证原来的触发场景。”根据任务复杂度使用相应[工作流](../payload/.agents/workflows/README.md)，不需要每个任务都经过同样长的流程。

## 打开项目大盘

接入或升级体系后，可以直接对 AI 说“帮我打开擎天大盘”。也可安装命令行工具：

```sh
npm install -g @nextclaw/qingtian
qingtian dashboard
```

命令行工具需要 Node.js 22.12+。大盘的使用与边界见[项目大盘](dashboard.md)。

## 更新已有项目

让 AI 重新读取同一入口，检查当前安装状态，预览升级差异，再执行适用的升级与核对。共享体系与项目自身规则分别维护；一次升级不会批量修改所有项目。

## 了解当前边界

已有工作流和资料不等于模型总能可靠遵守。面向非专业用户的完整委托、异常恢复与持续自治仍需验证。当前事实见[当前能力与边界](current-state.md)，使用者遇到的问题见[问题树与价值分析](developer-pain-points.md)。
