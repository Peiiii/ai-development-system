# 阶段展示与接入初始化修复

## 目标、根因与设计

2026-10-14用户指出其它会话经常漏标记，并要求检查安装初始化。原安装器只验证受管文件，插件默认关闭、项目手工配置、同阶段进度允许省略，文件接入不能证明宿主已加载。

最小改动：install/upgrade在未配置的managed模式中自动追加一条项目自有开启行；保留明确开启/关闭；冲突在写入前拒绝。skip模式不修改项目AGENTS。新增check --readiness，检查Lifecycle路由和单一配置；首条真实工作消息仍由实际宿主观察，不能以静态检查伪造。共享AGENTS补每条消息唯一标记与通用兜底；插件原owner补同阶段展示，不新增Skill、状态库或宿主钩子。

## 方案与实现Review

风险：默认启用改变展示但不改变权限或开发阶段；明确关闭必须保留；升级不能覆盖其它WIP；代码块里的配置示例不能误作生效配置。实现已将项目自有文本与受管段分离，忽略围栏示例，冲突先于applyChanges。没有宿主输出拦截接口，既有会话重新注入与所有未来响应均不得声称已保证。纯规则接入不启动大盘或产品任务。

## 验证与交付

验收覆盖：新安装默认配置、dry-run零写入、升级保留关闭、缺失配置一次补齐、重复升级幂等、install/upgrade冲突零写入、skip模式不修改项目、配置文档示例不误判、原升级冲突保护与包分发。`npm run check`通过57项受管文件与链接检查；`npm test`全量23项通过，其中安装器定向12项。当前ai-content-studio升级4项受管资产/入口/锁，check --readiness确认enabled。当前会话按升级后的官方格式输出；未创建其它会话或宣称所有既有上下文已刷新。发布结果继续按实际回读登记。

## 回退与复核

沿Git恢复本次installer/payload改动；目标项目明确关闭专属格式即可保留选择，通用标记沿用户全局规范。后续真实新会话检查首条、同阶段进度和最终答复是否有且只有一个准确标记，不用历史输出倒造证据。
