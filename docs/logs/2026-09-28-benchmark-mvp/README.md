# DevWeave 测评 MVP：首次远程实跑

日期：2026-09-28。状态：MVP 已在远程 Linux 机器运行；结果只适用于 Task Inbox 这一项小型开发任务。

## 用户目标与本批范围

用户希望 AI 开发体系接受模糊目标后，自主完成必要判断、实现、验证与交付，减少用户逐项 Review 和催促。本批把可复验的固定任务、Codex CLI 对照运行器、独立验收和成本记录落在 DevWeave 上游仓库；不要求接入项目增加 CI。个人长期目标另见个人知识库 `docs/thoughts/2026-09-28-low-supervision-ai-development.thought.md`。

## 环境与方法

- 可信远程 Linux x64 VPS，专用普通用户；Node 22、Codex CLI 0.158.0、ChatGPT 订阅登录、GPT-6 Luna、medium 推理设置、`workspace-write`。
- 同一 fixture SHA-256：`dcd2095e09dd38ffc4289dfba4e7ee0c522ccd862baaf1f475ca649bb1ace0fb`；同一中文目标提示。baseline 不安装 DevWeave，treatment 用正式安装器接入后再启动 Codex。
- 两组独立 Git 工作目录，顺序运行，无任务中途人工介入。grader 在工作目录外，运行后执行。事件、退出状态、补丁、验收及 Token 保存在远端私有结果目录；本地仅保留不含认证信息的摘要、补丁与 grader 输出。
- 完成交付必须同时满足 Codex 正常结束、给出最终回复、所有验收通过。超时即使代码已通过测试也不计完整交付。

## 预设五项验收的原始结果

| 批次 | 时限 | 组别 | 代理结局 | 预设验收 | 耗时 | 输入 Token | 缓存输入 | 输出 Token |
| --- | ---: | --- | --- | ---: | ---: | ---: | ---: | ---: |
| 探路 | 360 秒 | baseline | 完成 | 5/5 | 100 秒 | 144,382 | 131,840 | 3,474 |
| 探路 | 360 秒 | DevWeave | 超时，未交接 | 截止时 5/5 | 360 秒 | 未知，缺少结算事件 | 未知 | 未知 |
| 完整对照 | 600 秒 | baseline | 完成 | 5/5 | 222 秒 | 482,617 | 447,744 | 7,842 |
| 完整对照 | 600 秒 | DevWeave | 完成 | 5/5 | 357 秒 | 1,382,529 | 1,303,808 | 10,776 |

完整对照中，DevWeave 组耗时为 baseline 的 1.61 倍、总输入 Token 为 2.86 倍、去掉缓存输入后为 2.26 倍；订阅额度消耗不能由 Token 直接换算为 API 账单。两个基线样本的耗时也从 100 秒变到 222 秒，不能据此做稳定的收益百分比结论。

## 事后发现与 grader 修订

自查补丁发现初始 grader 没有覆盖并发写入。事后在本地对两组产物同时执行 20 次 `add`：baseline 成功 20 次并保留 20 条，DevWeave 成功 20 次但只保留 12 条。baseline 实现了文件锁和同步落盘，DevWeave 使用原子替换但没有串行读改写，因此可能丢失已确认成功的任务。

把并发添加加入**下一版**独立 grader 后，在远端对原两组产物直接复验：baseline 6/6、DevWeave 5/6。这是事后探索性结果，不能回写为原始预设五项的分数；从现在起新运行使用六项并记录 grader SHA-256。并发测试仍只是一类可靠性边界，不代表完整产品质量。

## 结论、证据和限制

本批证明了远程订阅 Codex CLI、固定任务、双组隔离、结果记录和独立验收的完整运行链路。它没有证明 DevWeave 在模糊目标下更可靠；本任务的首轮证据反而显示更长耗时、更高 Token，且遗漏并发持久化边界。不能据此宣称 DevWeave 整体无效：任务小、样本少，执行顺序和模型状态未充分随机化。

本地可核查产物位于 `benchmarks/results/remote-2026-09-28/`（被 Git 忽略）；远端原始事件及工作目录位于 `/home/devweave-bench/ai-development-system/benchmarks/results/2026-09-28T13-39-16-923Z/`。两组事件中未发现读取 grader 文件的记录，但 grader 与代理同机同用户，仅位于工作目录外，尚不能作为防窥的公开排行榜。下一批公开可引用测评需隔离 grader 权限、预先冻结题目与验收、交错重复并加入未调优任务。

本批未修改 DevWeave 核心规则。单例失败先用改进后的验收和更多任务验证，再判断是否需要缩减流程开销或调整规则；不为一次遗漏新增常驻提示词或接入项目检查。

验证记录：上游 `npm run check` 通过（43 个受管文件）、`npm test` 6/6 通过；本地与远端的 `node benchmarks/run.mjs --check` 均能识别起始项目未交付；修订后的 grader 在远端原工作目录复验为 6/6 与 5/6；伪 Codex 完整跑通运行器事件解析与可逆补丁产物。原 CLI 案例源码无额外运行时依赖。

## 在线前端交付扩展

用户随后明确要求每次完成的开发结果都能通过 Cloudflare 链接验收，并有历史管理和删除入口。因此新增固定网页案例 `web-board`，不改原 Task Inbox 历史成绩。VPS 同一专用用户用 GPT-6 Luna medium 完成一轮 DevWeave 组：Codex 正常结束，用时 549 秒，输入 685,939 Token（其中缓存 636,160），输出 15,368 Token。未运行该网页案例的 baseline 组，不能给出对照优势结论。

初版网页 grader 为 5/6：完成状态一项错误地要求未写进 fixture 合同的 `data-completed` 属性，而页面使用可访问的 `aria-pressed`，且真实点击、刷新后都维持正确状态。保留 `grader-v1.tap`、原始 grader SHA 和 5/6 结果；将 v2 检查改为可访问状态后，**同一份未修改代码**通过 6/6。该 6/6 是明确标注的事后校正，不是首次预注册成绩。远程原始事件和本机复制件均保留在忽略 Git 的 `benchmarks/results/2026-09-28T14-59-14-205Z/`；在线报告同时附两版 grader 输出和修正原因。

通过校正验收后，将生成源码与设计文档提交为 `263860888fd6b94f8ced2fae01d6ae24f4a1321f`，上传包含 Git 历史的源码包、报告和单文件前端到 Cloudflare R2。在线预览：[日常任务板](https://2026-09-28t14-59-14-205z-1-devweave.devweave-preview.nextclaw.io/)；管理入口：[DevWeave Lab](https://devweave-lab.nextclaw.io/)。用户随后要求每个结果使用专属四级域名；Cloudflare 通配 DNS、证书和 Worker Route 已实测，旧 `/runs/<编号>/` 链接返回 302 到新域名。线上 HTTPS 返回 200，真实浏览器在新域名再次验证新增、刷新持久化和 390px 手机布局无横向溢出。管理面板显示新域名链接与下载/删除按钮；独立测试记录证明管理 API 无密钥 401、删除后列表移除且旧预览 404。每次预览及管理面板使用不同浏览器 origin，生成代码无法读取面板的会话密钥。

本机 `npm run bench:remote -- --check` 已通过从打包、SSH、远程依赖安装到起始版浏览器验收的单命令预检。后续完整运行会由同一命令取回 tar 归档、发布通过的结果，并在成功后清理本轮 VPS 临时目录。单轮网页任务只能证明这项交付链路；公开宣传前仍需更多预先冻结的案例与对照重复。

域名迁移时临时创建过该运行的精确 Custom Domain 用于证书诊断，随后已移除，最终流量只走通配 Route；临时 Worker Preview 也已删除。Cloudflare 不会随 Custom Domain 删除自动删除其证书；当前 Wrangler OAuth 对证书清理 API 返回 403，留有一张不影响服务的闲置精确证书，后续具备证书管理权限时可按对应域名清理。永久方案不为每次结果创建 Custom Domain 或 Worker Preview。
