# 恢复项目发现，移除脚本开发入口

2026-10-24 用户指出 0.1.13 的两个回退：把 package.json 命令当成普通项目的主要价值展示；默认移除 ~/Projects 发现导致旧项目消失。本轮按纠正直接修复，不新增 AI 任务执行功能。

根因除了默认范围缩水，还包括 README 被当成项目终止标记：explorations 是工作空间容器，阻断了下方 42 个旧项目。恢复当前工程、登记列表、~/Projects 的默认范围，使用有界广度优先目录发现；README 容器有子项目时不作为项目，Git/工程清单和已安装体系目录确定项目边界后不继续扫描源码。目录发现最多 15,000 目录、100,000 项、1,000 项目、深度 5、5 秒软预算，达到限制明确提示，部分结果保留已知目录；不以此宣称所有磁盘目录均已读取。

CLI 先提供当前项目，随后一次后台目录发现；前端一次请求补全列表，没有轮询或全项目正文索引。其它项目仍在选择时读取，现有正文缓存、分页与增量读取预算保持。移除“开发入口”、脚本计数、Git 按钮及前端自动 info 请求；旧只读 API 保留兼容。

实际本机以 0.1.12 默认发现的 58 个项目作集合基线，58/58 全部恢复，连同普通未安装项目共 178 个。服务监听 26 ms，真实页面首次资料就绪 728 ms（含 Chromium 启动），正文读取 1 篇，来自当前未安装工程，其它项目正文读取 0；脚本区块 0，页面错误 0。证据 [本机回归](2026-10-24-dashboard-discovery-fix/local-regression.json)。目录发现单独实测 281 ms；暖文件缓存，不是跨设备或冷盘保证。

41 项 Node 回归、六组浏览器回归通过。100 个普通项目、每项目 81 篇资料，20 次新服务及页面上下文：P50 327 ms，P95 564 ms（含后台发现、同进程且 OS 文件缓存未清空）。覆盖旧容器下已安装项目不丢失、当前项目优先、其它项目零正文读取、无脚本入口、搜索/Skills/知识/抽屉/切换/手机展示。证据 [性能样本](2026-10-24-dashboard-discovery-fix/performance.json)。

主代理已复查发现边界、异步补全、停止中止、部分发现与兼容 API，无独立代码评审。版本升至 0.1.14；发布与本机当前服务切换结果完成后追加。本轮不触碰其它任务尚未提交的视觉升级 current-state。
