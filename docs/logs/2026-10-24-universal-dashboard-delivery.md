## 实现与性能约束

- 项目发现支持 Git/worktree、常见工程清单、资料项目及明确添加的普通目录；默认仅当前工程与登记列表，不递归扫描 ~/Projects。从子目录启动优先找工程根，容器目录不冒充项目。
- 服务先识别项目后监听，不读文档正文；页面通过 bootstrap、按项目 API 和后端分页（默认 30、最多 40）读取。搜索和类型过滤在项目范围内执行，旧 snapshot/search 客户端保留当前项目语义。
- `lib/artifacts.mjs` 继续拥有唯一资料读取/分类/解析；新增根 AGENTS/CLAUDE 知识，所有 Markdown 仍执行安全读取。`lib/project-index.mjs` 管理项目级请求合并、全局串行索引、最多 4 项等待、两项目/16 MiB 正文缓存和 30 秒访问触发 TTL。未变正文复用，重新有限枚举以发现新增删除。
- 每项目 8 MiB/2,000 文件/12,000 项/2 秒软扫描预算，迭代目录而非一次 readdir 整目录；每 32 项让出事件循环。部分读取不能覆盖已有完整快照。慢文件系统操作不能被软时间预算硬中断；快速切换不展示旧项目返回，已开始的扫描仍受上述预算约束，服务停止会中止后续扫描。
- 普通项目展示开发命令；没有工作记录不画空推进卡片。Git 由用户点击才执行只读命令，单命令 750 ms/64 KiB、一个活动进程、最多两个排队请求，无周期 Git 或递归 watcher。开发命令只展示，不新增执行端点。
- 总览仅汇总已读取缓存，并显示覆盖度；显式点击全局待关注至多读取前两个项目，避免隐式后台扫描全部项目。文件存在仍不表示宿主加载或任务完成。
