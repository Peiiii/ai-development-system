# 擎天命名与跨项目大盘

## 来源、范围与用户链路

来源见[原始输入](../logs/2026-10-07-qingtian-dashboard/README.md)。用户已确认整个体系统一为“擎天 / qingtian”，授权完整实现、提交、推送、官网与 npm 发布。feature / standard / L4；design-document: required；plan: required。属于现有体系新增工具，留在本仓库，非独立探索应用。

首次用户安装 npm 包后运行 `qingtian dashboard`，命令输出本地地址并自动打开浏览器。在已有接入项目的机器上发现项目，首页看到项目列表、明确记录的进展、待关注事项和最近产物。点击项目筛选，再点击产物阅读原文和关联资料，返回总览继续查看。搜索可跨项目查找正文。刷新重新读取项目文件；退出终端停止服务，重启仍保留登记项目。空目录明确给出 `qingtian projects add <path>` 与 `--root <path>` 入口，文件或目录失败呈现提示，不伪造零产物。

## 技术与职责

2026-10-08 发布修订（scope 2）：用户明确授权在独立包名无法发布时复用 nextbot 的 npm 命名空间。实际发布名采用 `@nextclaw/qingtian`，bin/产品展示名仍为 `qingtian`/擎天，官网归档 URL 保持 `qingtian-<version>.tgz`。构建读取 npm pack 返回的实际文件名再归一化公开归档路径；真实 scoped 包从 registry 的隔离安装覆盖此变化。凭据为本机用户级配置，不进入源码、产物包或项目事实。

沿用 Node.js ESM；旧独立安装器继续支持 Node 20+，新 npm CLI 与大盘采用 Node 22.12+，本机 22.23.2 已确认。采用原生 HTTP 与无构建浏览器界面，少量 Markdown 依赖 marked 18.1.0 / sanitize-html 2.18.0；官方说明 marked 不负责净化，HTML 必须独立净化。实查 npm audit 后，sanitize-html 2.17.0 有已知问题，使用已修复且要求 Node 22.12+ 的 2.18.0；不降低依赖版本迁就新工具尚无用户的旧运行时。相较 React/Vite，当前列表、搜索、原文读取无需构建与框架运行依赖；相较终端 TUI，网页更适合中文长文、表格与跨文档链接；云同步没有本次用户需求。新版运行要求在 help/package/README 一致传播；官网下载旧安装器不加载大盘依赖。此修订方案 Review 通过，现有项目安装合同未变。

`bin/qingtian.mjs` 拥有统一命令入口；现有安装器导出同一 main，新旧入口调用同一实现。旧脚本、受管标记、锁文件和公开下载 URL 已有真实消费者，作为安装兼容合同保留；产品展示名统一为擎天，不复制安装器。

项目登记在 `~/.qingtian/projects.json`（可用 QINGTIAN_HOME 隔离），仅 CLI projects add/remove/list 或成功的非 dry-run 接入改变登记。扫描只读，默认从 `~/Projects`（不存在则 cwd）和当前目录发现，显式 --root 可覆盖默认扫描根。识别既有锁文件和本体系源仓库；跳过依赖、Git、构建、结果和软链接。按规范实际路径去重，登记路径失效可见。有限目录/文件预算，截断明确提示。不会向其它项目写大盘状态或修改规则。

项目文档是事实 owner，索引是可丢弃投影。读取 README、docs、wiki、.agents/wiki/knowledge 的 Markdown；设计、计划、work 当前状态、日志、track、recurring、loop 形成分类，任务关联优先显式 Markdown 链接，目录同主题为辅助。保留正文、路径、更新时间、状态原文和来源，不把数量等同进度，不由 mtime 推断运行，也不把日志的局部已发布当整体完成。没有明确状态显示“待核实”；周期与关注只呈现文档意图，实际后台运行未知。

## 界面与可用性

品类是跨项目工作台，首屏主角为项目清单和待关注事项。用 oil-ui 比较两个小样后自主确定方向并留档：A 白色工程工作台（蓝色状态、横向项目清单与右侧关注栏）；B 深色终端式紧凑总览。选择 A：适合日常扫描中文与原文，内容密集而无需终端模拟。视觉变量统一，导航小、项目名强、判断依据与日期弱；没有营销横幅。窄屏换为单列，原文阅读可全屏，键盘与关闭/返回可用，搜索和分类可组合，加载/空/失败状态明确。三处动效服务筛选、阅读面板和刷新反馈，并尊重 reduced-motion。

## 本地边界与恢复

HTTP 仅绑定 127.0.0.1；随机会话凭据在 fragment 传给界面，经 Authorization 访问数据，不写项目或日志。拒绝异源 API、错误 Host 和无凭据调用。只开放静态界面与只读索引/文档 API；文件按已索引 ID 读取，realpath 再核验根边界，拒绝软链接和任意路径读取。净化 Markdown，禁 script、事件属性、远程图片与危险协议；内部链接只打开已索引 Markdown，外链需明确点击。文件消失、变大、解析失败单独报告；刷新失败保留旧视图并标明失败。启动端口默认自动分配，可指定端口；Ctrl+C 关闭服务。公开 npm 包通过 files 白名单，仅发布 CLI、运行库、界面、payload、manifest、检查器和公开 README，不包含私有日志、配置、测评证据或项目清单。

## 验收与方案 Review

黄金链路：干净临时目录从打包 tgz 安装，运行 qingtian install/check/upgrade（含 dry-run 与冲突），登记并发现项目，启动 dashboard，在浏览器跨项目搜索正文→打开文档→沿内部链接→返回→修改原文刷新→观察新结果。旧入口安装/升级保持通过。真实本机项目可发现并打开原文，桌面与手机无横向溢出；空/损坏/超限/丢失/无凭据/XSS/越界读取有实际判定。

契约见[验收账本](../work/2026-10-07-qingtian-dashboard/acceptance-contract.md)。抽象审计：保留统一安装器、项目登记、索引、服务和界面；无需数据库、云端账号、插件协议、自动派单和 AI 摘要服务，这些并非已确认结果。大盘只观察，不声称宿主运行。方案 Review 逐项反查原始目标、旧新入口、冷启动和发布：以上设计覆盖现有命名及产物不一致、局部发布与整体阻塞混淆、只读越界和首次登记等反例；design-review: passed，无开放 finding。实现 Review 与真实发布证据另记录。
