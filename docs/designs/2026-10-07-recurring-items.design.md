# 周期事项文档类型

## 来源与范围

2026-10-07，用户在自媒体机制讨论中要求沉淀账号方向与“每天找两个小红书帖子复刻、发帖”的事项，并完善 AI 驱动开发体系中的“定期事项”载体。用户已明确账号需要连续性，以 AI 小白、爱好者、学习者和希望使用 AI 的人为主要读者，长期建立能提供建议、咨询和解决方案的专业信任。栏目、制作方式与实际调度仍在讨论中；本次要求是保存方向、事项和完善文档机制，没有要求现在启动每日发布。

feature，standard，L3 文档路由和分发；plan:not-required，单批完成，跨仓库证据保存于同主题日志。共享规范在上游 payload 的知识治理 owner，内容定位与实例只在 ai-content-studio。两仓当前 AGENTS 均有精确提交、普通推送的授权，上游有官网分发授权。

## 选择与职责

已有 thought 保存战略探索；track 保存持续关注与最新判断；loop 定义证据驱动的循环实验。固定频率反复履行同一职责，需要每次交付和执行证据，无法仅用关注状态表达。选择新增 `docs/recurring/YYYY-MM-DD-<topic>.recurring.md`，中文名“周期事项”，由现有 project-knowledge-governance 的按需 reference 定义。扩展 track 会混淆观察与固定执行；用 loop 会强造实验和预算；独立 Skill 或调度器没有当前必要性。

周期文档保存稳定职责、意图状态、频率/时区、输入、每次动作与完成标准、授权来源、结果入口、异常与停用条件。调度真实状态由宿主维护，周期文档只记录关联 ID/入口和核对时点；详细逐次结果保留原任务/平台记录，周期文档只链接最近实际证据。草案与未配置状态不能写成正在运行；单次完成不结束周期职责。

主链路：用户要求沉淀定期事项 → 检索并复用同主题文档 → 保存职责和未决边界 → 明确调度是否配置 → 用户要求执行时核对意图状态、当前权限与实际周期证据 → 完成当次结果并回链。已配置宿主触发必须读取仓库当前文档；暂停/结束的文档阻止新执行，修改文档并不证明宿主也已停用。重复周期先查实际结果，中断或发布结果未知先核实，漏跑按明确补跑规则处理。

不新增 AGENTS 共享常驻规则、顶层 Skill、数据库、状态解析器或自动配置；lifecycle 只补知识治理触发，README/Wiki 提供导航。内容仓库一条项目规则链接定位与事项入口，不复制通用合同。

## 验收链路

- RC-01：定位文档保存用户明确的受众、连续性、专业信任与未来收入目标，AI 栏目建议单独标记；README 不再说账号方向完全未定。
- RC-02：要求沉淀每日事项时，创建可发现的 `.recurring.md`，具有频率、动作、质量标准、结果入口与异常边界；保存每日两个参考、目标两篇的原始想法，不把建议的“一次实践拆两篇”写成已确认。
- RC-03：普通一次任务沿原流程；观察用 track，实验用 loop；仅保存/讨论不启动调度；暂停/结束不重启，重复/中断先对账，不伪造每日完成。
- RC-04：上游 manifest、相对链接和现有安装/升级/冲突/分发检查通过；内容仓库真实预览升级、安装检查与内容 Skill 本机检查通过，项目规则保留。
- RC-05：两仓精确提交普通推送、fetch 后主线一致；官网包与线上 SHA-256 匹配，新合同能从实际公开包安装。

上述均 Required；active ledger 由同主题日志拥有。纯规则与内容文档按链接、语义场景和实际分发验证，不运行内容产品 build/tsc；未验证真实日更执行、受众增长和咨询收入，不把这些效果纳入机制文档交付声明。

## 方案 Review

逐项反查用户原话：定位与事项分别保存，机制具备固定职责而非仅观察；上游原 owner 和内容实例可接续，调度未配置边界明确。代表反例覆盖误启动、暂停、重复发布与伪造进展；未新增平行状态 owner。design-review: passed，无未关闭 finding。

## 复核与退出

本类型试用。第一批实际周期运行后检查是否减少职责遗失、重复执行和假运行表述；只在命中意图时增加一次 reference 读取。若长期仅有观察、没有重复职责，合并回 track；不因此自动增加专门 Skill 或后台系统。
