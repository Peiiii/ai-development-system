# 通用 Markdown 专注阅读与直达链接

## 用户链路与验收

用户从聊天中的文档预览链接进入阅读页，正文占主要区域，代码按语言高亮。点击文档内相对 Markdown 链接、另一项目的绝对 Markdown 链接或章节锚点后，在同一阅读区域继续；浏览器返回可回到上一文档。切换到第二份普通 Markdown，使用同一入口而非生成专用页面。失败时显示明确原因，并保留当前链接与重试入口。

前端不展示大盘项目侧栏、指标、任务列表或模态遮罩。路径在紧凑工具栏中展示，正文自适应侧栏宽度。窄屏代码默认换行，复制得到原代码。支持主题与章节目录。

## 复用与边界

复用 lib/dashboard.mjs 的本机服务、marked、sanitize-html、原始文件读取和现有主题/正文样式。增加 /read?path=<绝对Markdown路径> 专注页面及 /api/read；允许明确扫描根目录及已登记项目中的普通 .md，不要求文档进入大盘索引。规范路径、只读、大小限制、同源检查沿现有机制。

renderDocument 增加可选链接解析回调，默认大盘行为保留；阅读页把本地文档链接解析成另一条 /read 链接，锚点保留。新增 highlight.js 服务端高亮后继续净化 HTML；未知语言保持原文。高亮样式同时用于现有大盘阅读区。

不引入编辑器、账户、云上传或新 Markdown 渲染链。远端文档抓取和编辑/保存不在本次请求范围。原文不复制到工具仓库，私有 SDK 材料留在原项目。

## 入口与服务

qingtian read <file.md> [--port <port>] [--no-open] 提供可复用入口，内部沿用 dashboard 服务。固定端口可复用运行中的同版本服务；返回通用 /read 链接。交付时启动本机持久进程并给出真实可用链接，通过 open_in_codex 的 browser/right 入口展示；点击聊天链接的宿主路由若无法观察，必须与网页内跳转的验证区分。

## 验证

后端测试覆盖普通 Markdown、跨文件/跨项目链接、锚点、最新文件重读、未知代码语言、高亮后的 HTML 净化、路径越界/软链接/非 Markdown/过大文件及鉴权。浏览器验证真实 SDK 文档及另一份独立文档，检查高亮颜色、链接往返、窄屏、主题、代码复制与读取失败。

用户补充：读取不依赖文档索引。因此 readerOnly 模式启动跳过项目发现/索引，只使用明确根目录与项目登记确定只读范围；/api/read 直接读文件。普通大盘保留旧索引流程。项目 Markdown 内链接的 TS/JS 等源码也可按代码预览，共用高亮与路径限制；不变成文件编辑器。实际交付根目录覆盖用户项目目录，第二份未收录文档也必须可读。
