# 测评结果在线交付设计（2026-09-28）

## 背景与目标

首次测评只产生 CLI 代码、补丁和测试报告，用户无法通过前端链接验收。当前目标是：给固定但不穷举细节的开发任务，远程用订阅内的 GPT-6 Luna 完成；通过浏览器验收后保存 Git 提交；每个结果有独立 Cloudflare 预览链接；同一个在线面板可查历史并删除结果。接入 DevWeave 的项目不需要增加 CI 或部署配置。

## 主链路

1. 操作者在本机运行 `npm run bench:remote`。本机将当前测评源码打包送到专用 VPS 普通用户的全新目录，远程执行 Codex CLI。固定任务是单文件日常任务板，提示允许 AI 自行设计布局与细节。
2. 远程使用 Playwright Chromium 跑六项浏览器验收。只有 Codex 正常结束且全部通过时，才在本轮 Git 工作区提交代码，并形成包含 `.git` 的源码包、测试输出与交付清单。失败留在远程结果目录，不冒充交付。
3. 本机取回结果后，用已登录的 Wrangler 把页面、源码和报告上传到独立 R2 bucket，最后上传 manifest 作为可见性标记。单轮路径是 `runs/<id>/`。
4. 独立 Worker 用 R2 binding 提供管理 API 与预览。管理域名 `devweave-lab.nextclaw.io` 只提供受密钥保护的历史列表、源码和报告下载、删除动作；`<运行编号>.devweave-preview.nextclaw.io` 通过一条通配 Worker Route 读取对应 R2 对象，每次结果有自己的浏览器 origin。Cloudflare Preview 域名设置负责自动配置通配 DNS 与证书，不为每次结果创建 Worker Preview，避开其数量上限。旧的 `/runs/<编号>/` 路径兼容跳转。
5. 管理面板删除时清除该运行的所有 R2 对象。列表与预览仅认 manifest，因此未上传完或已删除的结果不会展示为已交付。

## 验收

- A1：起始网页无法通过固定浏览器验收；远程 GPT-6 Luna 完成后，报告记录模型、提示/fixture/grader 指纹、耗时与 Token 用量；未结算用量如实标为未知。
- A2：通过验收的源码有干净 Git 提交，源码包可下载，提交 SHA 与报告一致。
- A3：每个已通过结果有可打开的专属四级域名 Cloudflare HTTPS 前端链接，手机宽度无横向溢出，交互和刷新持久化在真实浏览器可用。
- A4：统一面板显示历史结果，能下载源码/报告并删除；删除后列表消失，旧预览链接返回 404；无密钥无法调用管理 API。
- A5：后续运行通过一条本机命令完成远程运行、取回证据和 Cloudflare 发布；目标项目无需额外集成。

## 边界与取舍

- 当前测评案例要求单文件静态前端，避免为 MVP 引入构建产物和后端状态。后续案例需各自定义可部署产物与验收，不把此限制写入 DevWeave 通用规则。
- 预览是公开链接，面板数据与删除操作用随机密钥保护。密钥仅保存在本机私有文件和 Cloudflare Worker secret，不复制到 VPS 或源码；面板在当前浏览器会话内保存输入的密钥。
- R2 是在线交付存储，不作为测评的唯一证据库；本机忽略 Git 的结果目录保留取回的原始运行证据。确认本机取回并发布成功后，自动清理本轮 VPS 临时源码和结果，控制远程磁盘占用。面板删除清理 Cloudflare 在线历史，不删除本机审计副本。
- 六项浏览器检查只证明该固定任务的行为。它不能证明 DevWeave 对任意模糊目标都能可靠自主交付；对外展示需同时给出样本数、失败和成本。
