# 官网愿景与核心挑战同步

2026-10-22，用户指出此前讨论和仓库文档没有体现在官网，要求同步。范围是既有官网的内容与发布，不另做视觉改版，也不修改已发布的 CLI 版本。

## 依据与结果

- `wiki/vision.md` 拥有开篇愿景原句、非专业用户与自治理的补充、五点解释、依托 Codex / Claude Code 的定位边界。
- `wiki/core-challenges.md` 拥有五类当前挑战、难点、候选方向与验证方式。
- `wiki/system-architecture.md` 与现有 workflow atlas 继续拥有三层架构和流程；首页沿用现有交互架构图。
- 首页增加愿景与挑战入口，完整呈现两段愿景和五点解释；挑战可展开阅读问题、方向和核验方式，并链接权威正文。明确愿景与当前实现的区别。

## 实现

在现有静态构建链中解析上述 Wiki，用同一内容生成首页区块，避免手工复制形成第二份正文。沿用深色、荧光绿、字体、间距与现有组件风格；新内容使用语义化区块、列表和原生 details，覆盖桌面与手机，保持键盘可用。内容源缺失或预期结构无法读取时构建明确失败。

内容发布增加 `--content-only` 构建模式：先验证已存在的发布归档、校验文件与 SKILL 入口，保留其字节，再更新页面和 Wiki。当前官网公开的 0.1.12 产物先保存并核验，最终内容部署沿用该发布，不用当前 README 重打同版本 npm 包。

## 验证与交付

检查构建内容与 Wiki 原文一致、两段愿景完整、五点解释及五类挑战完整；改变源内容后生成结果相应变化，源结构缺失时失败。验证内容构建前后发布归档与 SKILL 字节不变。运行既有 payload / 分发检查、官网流程浏览器回归；新增内容在 1440 / 800 / 390px 验证导航、展开、原文入口、无横向溢出、无运行错误，实际看图核验桌面和手机。

实施前方案自查：数据流复用 Wiki 与现有构建；新模板只负责展示；发布前先验证不可变分发文件，避免把同版本包内容替换。无未闭合方案问题，允许实施。完成后记录实际测试、发布身份、公开内容与分发文件回读证据，精确提交并普通推送 main。
