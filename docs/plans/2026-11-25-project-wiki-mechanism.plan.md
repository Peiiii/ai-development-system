# 项目 Wiki 维护机制实施计划

目标：落实[已确认设计](../designs/2026-11-25-project-wiki-mechanism.design.md)，集中 Wiki 维护职责，保留设计、任务记录与方法的原 owner。

架构：原事实合同提供 Wiki 窄入口，Lifecycle 集中协作；不向各阶段追加 Wiki 提醒。沿用当前 checkout，隔离并发改动。用户要求不用子代理，核验与 Review 由当前 Agent 执行。

| 步骤 | 动作 | 完成标准 |
| --- | --- | --- |
| 1 | 修改知识治理 Skill、事实合同和 Lifecycle | 两个操作、Wiki 写入范围、源资料 owner、接续与完成判断完整 |
| 2 | 同步架构、产物 Wiki、当前事实、README 与原设计 | 对外说明与执行合同一致 |
| 3 | 直接核对反例，运行 `npm run check`、安装升级和分发测试 | 真实旧快照升级、自有 Wiki/设计/日志字节保留及冲突保护；不以关键词测试替代行为验证 |
| 4 | Review、补版本、构建发布官网归档与 npm 包 | 公开回读摘要、隔离安装与本次规则一致 |
| 5 | 补日志，精确提交推送 `origin/main` | 排除已有 visual-upgrade 状态改动，分别报告文件接入与模型执行效果 |

纯规则不运行产品 tsc 或无关 UI 截图；安装包执行既有分发验证。实际宿主重新加载与长期跨项目效果不由静态检查推断。

执行结果：全部步骤完成。0.1.22 已通过 OIDC 发布，公开 tgz 摘要一致、CI 幂等重跑及 registry 隔离安装通过；详见[发布验收](../logs/2026-11-25-npm-trusted-publishing/README.md)。官网状态同步与本次记录提交推送沿仓库发布流程收尾。
