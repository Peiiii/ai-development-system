# 通用项目大盘与性能约束 Implementation Plan

> 2026-10-24 用户纠正：下文实验方案中“默认只发现当前项目/登记列表”和脚本“开发入口”的建议已撤回。正式 0.1.14 恢复 ~/Projects 的有界后台目录发现，保留旧项目可见范围，正文仍按选择加载，移除脚本区块；以[修复交付记录](../logs/2026-10-24-dashboard-discovery-fix.md)为准。

**Goal:** 未安装擎天规则的普通项目也能直接使用大盘，且项目数量增加不拖慢当前项目首屏，不产生默认后台全盘扫描。

**Architecture:** 将「项目发现」「当前项目轻量概况」「资料索引」「正文阅读/搜索」「Git 活动」拆成按需阶段。沿现有 projects、artifacts、dashboard 与前端 owner 修改，项目目录仍拥有事实；大盘索引可删除重建，安装记录只表示接入能力，不再充当浏览资格。

**Tech Stack:** 现有 Node.js 原生文件/API/子进程模块、原生浏览器界面、node:test 与 Playwright；第一阶段不增加数据库、文件监听器、搜索服务或后台常驻进程。

## 已确认的问题

- `lib/projects.mjs:isProject/changeProject/discoverProjects` 以安装锁或体系源码标记作为项目身份；普通 Git/工程项目不能发现或登记。
- `defaultRoots()` 默认加入整个 `~/Projects`，发现阶段允许 15,000 个目录、五层深度。放宽识别但保留这个默认行为，会把无关项目引入首屏成本。
- `lib/dashboard.mjs:startDashboard/refresh` 在监听服务之前发现所有项目并调用 `indexProjects(paths)`；刷新也重建全量索引，虽已有并发刷新合并，但没有项目级缓存。
- `lib/artifacts.mjs:indexProjects` 读取全部所收录 Markdown 正文，默认全局 10,000 文件/128 MiB、每项目 2,000 文件；这些是安全上限，不能当成首屏工作量预算。
- `/api/snapshot` 向前端返回全量文档元数据，前端再筛选当前项目；`/api/search` 每次构造并小写转换同资源类型的全局正文，当前项目条件没有进入后端查询。前端虽仅显示 30 行，尚未避免全量传输与筛选成本。
- 资料根目录固定，普通项目已有的根 AGENTS/CLAUDE 等入口与工程命令未呈现；无工作记录时「当前推进」没有数据。Git 历史和文件修改不能自动解释为任务已完成。

## 方案选择

| 选择 | 收益 | 成本/限制 | 结论 |
| --- | --- | --- | --- |
| 放宽识别后继续全量扫描 | 代码变化最小 | 项目越多，启动、刷新、内存及搜索越差 | 不采用 |
| 当前项目优先、分阶段加载、有限缓存 | 无项目安装即可用，扩展后仍能限制单次工作量 | 前端必须表达未索引、部分结果与更新中 | 推荐 |
| 一开始建持久数据库、递归 watcher 和后台索引器 | 有机会加速重复启动与跨项目检索 | 新增迁移、失效、驻留资源和后台治理成本 | 先不采用，真实数据证明必要后再评估 |

## 产品与数据路径

### 1. 启动只承担当前项目必需工作

在任意目录运行 `qingtian dashboard`；工具在电脑安装一次即可，项目浏览不要求安装擎天规则、不改目标项目文件。

- 优先显式项目目录或在有限父级内识别当前工程。Git `.git` 目录和 worktree 的 `.git` 文件、常见工程清单、既有擎天标记分别作为信号；显式添加的普通目录允许作为资料项目，不拿某一种语言清单充当所有项目的前提。
- 不再默认递归扫描 `~/Projects`。首屏可读取既有本机登记列表，但其它项目只显示保存的名称/路径及「未读取」，不能在没有数据时显示 0 份资料或推断可用。
- 当前项目初始读取有限的工程清单以展示名称/命令来源；不执行命令，不启动 dev server，不读完整源码、不跑 Git、不索引所有 Markdown。
- 项目发现与接入状态分离：安装锁损坏需明确提示，不静默降级为未安装；已有接入项目获得原有能力。
- `--root` 的目录发现单独按需执行，分批返回。目录项枚举、祖先查找、返回项目数均有限额，命中工程根即停止普通下探；monorepo 子项目通过明确 workspace 配置或显式目录进入后续适配，不在第一版猜测所有嵌套项目。

### 2. 当前项目资料按需索引，其它项目不随之读取

页面概况先可操作，再发当前项目资料请求。继续保留「项目产物 / 项目 Skills / 项目知识」，按存在的数据展示推进；普通项目突出概况、资料、开发入口和可按需读取的最近活动。

- 先用约定的资料根目录，不扫描整棵源码树；现有 README、docs、wiki、项目 Skills 基础上增加根 AGENTS/CLAUDE 等明确入口。额外文档位置由用户显式指定，未来适配器返回候选位置，不能任意扩大扫描范围。
- 目录迭代用 `opendir`，在枚举阶段限制目录项数量。单纯 `readdir` 后截断不能限制巨大目录的分配成本。
- 元数据列表与正文分离；API 带项目、资源类型、页码/游标和版本，默认每页 40 条，浏览器不接收全部项目的文档数组。
- 继续复用 `parseArtifact`、分类和 Skill 分组；不把文件存在宣称为宿主加载，不从 Git 提交猜测任务状态。
- 第一阶段允许对选中项目读取有预算的正文以保留原有摘要/搜索/状态能力；正文进入有上限的缓存。原型暂仅缓存一个项目，这比最终缓存设计更保守。

### 3. 刷新只针对项目，缓存失效保持正确

- 同一项目的并发索引请求合并；使用版本号/取消标记丢弃旧结果，不能把切换前的结果覆盖新项目。
- 首次完整扫描保存文件指纹（dev、ino、size、mtime、ctime）与解析结果。手动刷新重新有限枚举，未变文件不读正文，新建/修改文件重读，删除文件从完整结果移除。
- 不能仅以根目录 mtime 判断子目录是否变化。新文件、子目录新增、删除与重命名必须在再次枚举中被发现。
- 短期内重复打开可返回缓存，并清楚标识快照时间。候选 TTL 30 秒，只在用户再次访问/请求时检查；TTL 不启动周期轮询。手动刷新立即重新校验，显式强制重读用于时间戳异常等边界。
- 达到预算/超时/错误不能将部分枚举结果当完整结果剪掉旧文件；保留上次完整结果并提示旧快照，或明确标注部分结果、已读取范围及继续操作。
- 不为所有项目保留正文：候选 LRU 最多两个项目、正文合计 16 MiB，任一项目上限 8 MiB；切换到第三个项目或超限即驱逐，切换后重复加载属于明确取舍。第一阶段没有磁盘索引失效问题。

### 4. Git 和搜索均限制范围

- Git 卡片按需请求当前项目，最多两个串行只读命令；首屏和其它项目不生成 Git 进程。使用参数数组，无 shell；`GIT_OPTIONAL_LOCKS=0`、`--no-optional-locks`，禁用提示，无 fetch。
- 候选命令为 `status --porcelain=v1 -b -uno` 与 `log -5 --format=...`；不扫描未跟踪文件、不做全历史遍历。页面必须说明未统计未跟踪文件，不把该结果显示为全部工作区干净；未初始化仓库显示无历史。
- 每命令 750 ms 超时、64 KiB stdout 上限，失败只降级 Git 卡片，不阻塞资料或首屏；记录退出原因、释放子进程。真实平台需验证超时与清理，不能只依赖 UI 的 Promise 超时。
- 搜索默认传入选中项目与资源类型，处理服务端匹配和分页；保留已有防抖及过时请求丢弃。正文先在选中项目建立有限检索，避免每个键入都重读文件。
- 全项目搜索必须由用户明确切换，返回已经搜索/尚未搜索的项目范围，可取消、逐批执行；不能把未索引项目默认为无匹配。过大的单项目也显示索引覆盖度。

## 初始性能预算（待正式实现达标，不是已实现承诺）

| 工作 | 建议预算 | 超额处理 |
| --- | --- | --- |
| 当前项目轻量后端数据 | 本机参考环境 fresh process 中位数 <100 ms；不随其它项目文档量增长 | 非必需字段延后，显式不可用 |
| 浏览器可操作首屏 | 参考机 P95 ≤1 秒；100 个已登记项目相对单项目新增 ≤100 ms | 先呈现当前项目，其它列表分页；需真实浏览器采样验收 |
| bootstrap / 资料页 | bootstrap ≤128 KiB，默认每页 ≤40 条、响应 ≤64 KiB | 游标分页/摘要裁剪，保留原文阅读 |
| 当前项目资料扫描 | ≤2,000 文件、≤12,000 目录项、≤8 MiB 正文；单片 ≤250 ms | 分片、让出事件循环，显示部分/处理中；时间不是硬实时保证 |
| 全局目录发现 | 显式触发；候选每批 ≤2,000 目录项，深度 ≤3、最多 100 项/批 | 返回可继续范围，不静默扩大目录 |
| 内存 | 100 项登记、选中项目普通资料时总 RSS 目标 ≤192 MiB；正文缓存 ≤16 MiB | 项目级 LRU、有限正文；测量基线与增长，不能只看缓存字节 |
| Git | 默认 0 个子进程；请求时最多 1 个在跑、每条 750 ms/64 KiB | 超时终止并局部降级 |
| 空闲 | 无项目轮询、无递归 watcher、无周期 Git；CPU 目标 <1% | 定位驻留定时器；watch 前端开发模式不计普通使用 |

对于慢磁盘/网络挂载，用户态时间预算不能中断正在等待的内核文件系统 I/O。方案只能限制启动的新工作、分片及先返回页面；正式实现仍需测取消/断连后的清理，不能宣称任何磁盘下都在固定时间内完成。

## 可复现实验与证据口径

运行：`node benchmarks/dashboard-performance/run.mjs`；默认结果写入 `.local/dashboard-performance/results.json`，可传绝对输出目录。全部造数在系统临时目录，完成/失败清理；真实项目阶段仅只读当前仓库，不扫描其它个人项目。

- 1/20/100 个项目；每个项目 80 篇约 4 KiB 的 Markdown，加 README、Wiki、Skill，共 83 篇。加入 node_modules 文档与 >1 MiB 文件验证跳过。为公平比较现有全量路径，规模组均带安装锁；另有移除安装锁的普通项目正确性组。
- 每规模/方案各三次独立 Node 进程，交替先后；相同夹具对比现有发现+全量索引+快照序列化，与当前项目轻量数据+后续单项目索引+40 行元数据分页。
- 记录 wall time、CPU time、采样 RSS、事件循环延迟、Node 文件 API 调用数和读取字节、响应字节；同一 worker 的后续阶段 RSS 可能保留前期分配，不能各阶段相减解释为独立峰值。采样 RSS 可能漏掉短暂峰值；5 ms 采样分辨率以下的事件循环延迟不可靠。
- 「首屏」实验指后端轻量数据准备，不包含进程加载、HTTP、浏览器绘制。OS 文件缓存未清空，fresh process 不等于真实冷盘；三次重复只报告中位数与观测范围，不冒充 P95。
- 缓存正确性验证：重复访问零文件 I/O；无变更刷新零正文读取；修改一篇、同子目录新增一篇、删除一篇，只重读两篇，删除生效；预算超限不覆盖已有完整快照；字节/时间上限明确为部分结果。
- Git 只测选中项目的两条命令与子进程超时机制；原型没有 HTTP、持久缓存、跨项目全文搜索、真实浏览器分页或生产调度器，不能据此宣称这些能力已验收。
- 实验发现若不满足预算，先修分层/缓存方案再进入生产；不通过把数据删少或虚报零文档使指标好看。

## 实施顺序及每步验收

### Task 1：项目身份与默认扫描范围解耦

**Files:** `lib/projects.mjs`、`bin/qingtian.mjs`、`tests/dashboard.test.mjs`。

1. 添加失败用例：未安装的 Git/Node/Python/普通显式目录；worktree `.git` 文件；从子目录启动；损坏安装锁；当前目录超出其它扫描预算仍可见。
2. 将浏览身份与接入状态分开，显式添加不再要求安装；普通启动只查当前和登记列表；新增显式发现路径，跳过依赖/构建/隐藏目录和链接。
3. 用计数断言验证：普通启动不递归访问 home/兄弟项目，目录发现命中根即停且预算可见；空登记列表仍可查看当前项目。
4. `node --test tests/dashboard.test.mjs` 通过后做该步精确提交，不能修改 installer 语义冒充浏览资格。

### Task 2：轻量首屏与项目级索引

**Files:** `lib/dashboard.mjs`、`lib/artifacts.mjs`；若责任足够独立，新增 `lib/project-index.mjs`；`tests/dashboard.test.mjs`。

1. 失败用例覆盖 bootstrap 不读 Markdown 正文、不启动 Git，先监听服务；项目/资源类型/分页参数验证，默认不返回全局文档数组。
2. 保持原鉴权、Host/Origin、路径、文件大小、软链接与 HTML 净化边界；读取清单也使用有限文件句柄读取与 NOFOLLOW 等已有防护，不能直接照搬原型的简化路径读取。
3. 将索引改为按项目可等待/可合并任务，有限并发、预算、分片与失败状态由后端拥有；稳定文档 ID 和现有抽屉阅读链接继续工作。
4. 运行定向测试和上述 benchmark，保存实际调用数与 payload；单项目旧用例必须保留，不能以省掉其必要资料满足预算。

### Task 3：缓存、增量校验和取消

**Files:** 原 `lib/project-index.mjs` 或 `lib/artifacts.mjs` owner；`tests/dashboard.test.mjs`。

1. 写修改/新增/删除/重命名/嵌套新增、同时间戳不同大小/ctime、删除中断、权限错误、预算截断、跨项目切换、并发刷新合并的失败用例。
2. 实现完整快照版本、指纹复用、LRU 字节计账、显式刷新/强制重读；不能累积所有项目正文。旧结果只在版本符合时发布。
3. 模拟取消、页面断开、停服务，确认未继续扫描其它项目、无遗留 watcher/子进程；不能只在 UI 忽略结果而继续无限后台工作。
4. 测试零变化读取字节为 0，两个变化只读取两篇；预算/错误保留旧完整结果且标示陈旧；大项目多次切换的 RSS 不随切换次数线性增长。

### Task 4：普通项目概况、Git 与前端适配

**Files:** `dashboard/app.js`、`dashboard/index.html`、`dashboard/styles.css`、`lib/dashboard.mjs`；必要时新增 `lib/project-info.mjs`；既有浏览器测试。

1. 首屏有限卡片按数据能力展示；未索引不是零项，加载/部分/错误局部可见；分页由后端限制，侧栏项目数大时分页/窗口化，原生组件继续复用。
2. 命令仅展示来源和复制，不在本轮提供执行端点；Git 按需、有上限、有超时；原任务状态证据与 Git 活动分开。
3. 搜索带项目 scope，分页和覆盖范围一致；切项目/资源类型时丢弃旧搜索/索引响应，抽屉和关联阅读不丢失。
4. 真实浏览器测「启动命令到可操作首屏」、切换响应、DOM 数、网络 payload、阻塞长任务与手机溢出；至少 20 次样本报告 P50/P95，并在同机对比旧版的必要单项目体验。

### Task 5：发布门

**Files:** `tests/dashboard*.mjs`、`tests/package-smoke.mjs`、`wiki/current-state.md`、CLI 使用说明与启动 Skill。

1. 以一个真实未安装项目、一个已接入项目、一个大型 monorepo 验收；补 Linux/macOS（Windows 无实测则明示未覆盖）及慢盘/超大目录/长历史 Git 失败注入。
2. `npm run check`、`npm test`、`npm run test:browser`、`npm run test:package` 与性能门通过，检查 API、旧参数、原资料读取和升级兼容。
3. 安装副本共享说明回到 payload owner；按既有发布链升级版本、npm/官网分发与公开包回读。仅方案/原型本轮不触发这一步。

## 方案评审结论

评价重点是「必要工作量是否有界」，而非增加并发掩盖全量成本。先切断默认全盘发现、全项目正文加载、全局搜索和后台 Git 四条放大链，再做缓存。当前项目优先是范围与时序变化，不能被包装成已完成了同样的全局索引；全局能力按需交付并明确覆盖度。

具体实测、预算终止优化与尚未通过的生产门见 [验证记录](../logs/2026-10-24-universal-dashboard-performance.md)。本轮完成方案与隔离验证，后续按上述顺序进入生产实现。
