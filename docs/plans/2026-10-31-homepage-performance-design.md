# 官网首屏性能优化

用户反馈官网加载非常慢，要求大幅优化。09:31（Asia/Shanghai）开始，先保存当前发布站点为对照，再测受控网络和实际线上请求。

根因与方案：外部 Google Fonts 的 CSS @import 位于主样式开头，慢响应会阻塞首绘；删除外部字体依赖，使用本机系统字体栈。首页直接内联唯一 styles.css 源码的构建结果，移除首绘样式请求链；文档页继续共用该样式文件。首屏真实 JPEG 保留原尺寸查看入口，预览改为 720/1440 AVIF、WebP 与 JPEG 回退，按显示尺寸选择资源。复制/导航脚本保持立即可用，第三屏架构和工作流在进入可见范围前 300px 再载入，键盘聚焦与点击也会触发加载；失败提供可实际重试的入口。

构建给首页 JS、预览图片生成内容指纹，使用 Workers Assets 的 _headers 让这些确定字节的 URL 长缓存，HTML 保持重新验证，不让下一次发布被旧缓存挡住。不增加运行时框架、第三方脚本或后台服务。

验收：同版本 Lighthouse 移动端前后比较；真实线上冷上下文、禁用 HTTP 缓存、150ms 延迟、1.6Mbps 下行、4x CPU 三次样本；另设字体服务延迟 12 秒的对照实验。检查 CLS/TBT、首屏无字体/演示请求、实际复制、演示与网络失败重试、桌面手机视觉、公开资源缓存头和分发包原字节。实验成绩不代表全球用户 p75 或所有网络上的速度保证。
