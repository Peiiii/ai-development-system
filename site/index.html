03 / THE DEVELOPMENT FLOW

流程需要展示，但不能只有一条。

五条命名 workflow：四种基础任务流程，加上可嵌套它们的大型交付流程。lifecycle 管理阶段，Skill 提供方法，Wiki 提供事实。

标准任务

有方案空间或较高风险时，先设计与审查，再实现、验证和交付。

  1. 01理解任务
  2. 02方案设计
  3. 03方案 Review
  4. 04开发实现
  5. 05验证测试
  6. 06实现 Review
  7. 07交付
  8. 08复盘

简单改动

局部、可逆、风险低的改动走短路径，仍保留必要的验证和 Review。

  1. 01快速理解
  2. 02修改
  3. 03定向验证
  4. 04轻量 Review
  5. 05交付
  6. 06轻量复盘

问题修复

先确定预期、异常与根因，再按风险决定是否需要独立方案 Review。

  1. 01预期与异常
  2. 02复现与根因
  3. 03修复方案
  4. 04修复实现
  5. 05回归验证
  6. 06Review
  7. 07交付与复盘

项目初始化

新项目先明确环境与技术栈，通过方案审查后搭建，并验证首条真实用户链路；保留上下文与恢复入口。

  1. 01目标与项目接入
  2. 02技术栈与链路设计
  3. 03方案 Review
  4. 04项目与产品实现
  5. 05真实使用验证
  6. 06实现 Review
  7. 07交付
  8. 08复盘与恢复

大型交付 · 外层组合流程

跨工作项维护整体成果；内层可执行项目初始化、标准任务、简单改动或问题修复。子流程完成后，把结果与证据交回外层。

  1. 01整体目标与验收约定
  2. 02整体与当前部分设计
  3. 03选择工作项与基础流程
  4. 04执行并返回证据
  5. 05集成验证与缺口核对
  6. 06继续必要工作
  7. 07整体交付、复盘与完成

有缺口就继续或记录真实阻塞；子流程结束不能关闭整体目标。打开大型交付 workflow 正文 ↗

五条流程的实际文件见 Workflow 目录。大型交付与基础流程可组合，阶段调度和完成门仍由同一个 Lifecycle 管理；层次与嵌套见 架构 Wiki。

04 / ARTIFACTS & EVIDENCE

工程产物与证据，支撑完整交付。

贯穿 Agent 工作流、Skills、Wiki，承载方案、执行状态和验证结果，支持追踪、恢复与可检验的交付。

01 / THINK & DESIGN

想法与设计

记录问题、取舍和方案，让实现前的 Review 有明确对象。

docs/designs/YYYY-MM-DD-<topic>.design.md
02 / PLAN & WORK

计划与过程

复杂任务保留计划和跨会话工作笔记，便于继续推进和核对范围。

docs/plans/YYYY-MM-DD-<topic>.plan.md
03 / VERIFY & REVIEW

验证与审查

把测试证据、Review 结论和返工结果关联到本次任务。

验证证据 → Review findings → 修正
04 / DELIVER & LEARN

交付与复盘

重要交付进入日志；复盘再判断哪些经验该更新到原 owner。

docs/logs/ · 按项目约定命名
从任务到复盘需求与设计 → 实现与验证 → Review → 交付日志 → 复盘沉淀

设计描述方案，记录承载过程，验证结果支持对应范围的结论；文档存在不等于结果已获证明。共享命名规则还包括 thoughts/ 与 loops/ 的日期前缀、角色后缀，日志按项目约定命名。简单任务不强制创建空文档。阅读工程产物与证据 Wiki ↗

05 / THE EVOLUTION LOOP

自动进化，从复盘沉淀开始。

体系要随真实开发持续改进。当前机制仍处于早期，主要依靠任务收尾时的复盘，识别值得保留的经验。

01 / WORK

真实任务

观察结果、返工与重复沟通。

02 / REVIEW

复盘筛选

判断是否有可复用的增量。

03 / OWNER

找到归属

分流到流程约束、Skill 或 Wiki。

04 / CHANGE

更新并验证

在正确的上游修改，再检查效果。

CURRENT STATE · EARLY

现在是“复盘驱动”，还不是全自动闭环。

没有可复用增量时不新增规则；发现方法缺口时优先修正原 owner。后续会继续增强问题发现、跨项目验证和更新后的效果反馈。

阅读进化机制 Wiki ↗

06 / BUILT TO EVOLVE

接入之后，还能放心迭代。

目标不是复制一次规则，而是让共享方法拥有持续更新、可审查、可回退的来源。

A

先预览，再写入

安装和升级都支持 dry-run。已有同名文件发生冲突时会停止，不会悄悄覆盖项目内容。

↗
B

每个文件都有版本指纹

锁文件记录安装内容的摘要。check 能发现本地改动，也能识别上游是否有新版本。

◇
C

项目语义仍由项目决定

产品愿景、授权、环境和发布规则留在项目中；共享体系只提供可复用的方法。
