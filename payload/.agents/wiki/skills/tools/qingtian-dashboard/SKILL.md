# 打开擎天大盘

完成结果是当前项目可用的大盘及用户能打开的地址，也可切换其它已登记项目。项目无需预先安装擎天规则，大盘只读已有内容。直接执行已授权的启动请求；不要只返回命令让用户再操作，也不要为查看大盘进入完整开发流程。

1. 在当前项目目录检查 `node --version` 和 `qingtian --version`。已有可用命令直接使用；浏览未安装规则的普通项目要求 CLI >=0.1.13，旧版本先升级同一官方包。缺少命令或需要升级且 Node.js >=22.12 时执行官方安装 `npm install -g @nextclaw/qingtian --ignore-scripts --registry=https://registry.npmjs.org`，再核验版本。Node 版本不足、离线或 npm 权限失败时报告具体缺口，不用 sudo、改权限或猜包名；可用 `npx --yes --package=@nextclaw/qingtian qingtian dashboard` 避免全局写入失败，但不能解决不支持的 Node 或断网。
2. 若当前会话已有大盘完整地址，先复用原服务；原页面是鉴权错误且用户提供了完整 token URL 时，先打开完整 URL 重试，或用对应 Bearer 验证 API，不因错误页就重复启动。原服务不可用或确实不是目标项目时，才从当前项目目录运行 `qingtian dashboard`。本机默认无需 token；仅在用户要求会话鉴权时加 `--require-token`。默认优先识别当前项目（含从子目录启动），默认发现当前项目、登记列表与 `~/Projects` 下的本地项目，当前项目优先显示，其余项目后台有界发现，资料按选择加载。未安装擎天的项目也能浏览已有资料与 Skills；有明确工作记录才展示推进。其它发现或登记的项目可在侧栏切换。仅用户指定扫描范围时用 `--root <绝对目录>`；可重复指定。当前项目位于其它位置、需要长期加入时用 `qingtian projects add <绝对目录>`。
3. 保持服务运行：使用宿主提供的持久终端/执行会话；不要在普通会被销毁的短进程里启动后立即退出。CLI 默认自动打开浏览器；宿主需要自己展示页面时可用 `--no-open`，取得实际输出的完整 URL 后用宿主的打开浏览器/文件面板工具打开。没有可用页面工具时给用户完整可点击地址。不要猜固定端口或复用已过期的会话凭据。
4. 验证真实可用性：查看页面已加载当前项目/产物或明确的空态；无法看页面时读取同一地址的 `/api/bootstrap` 核对当前项目，再请求 `/api/project?project=<当前项目 ID>` 验证资料可读（旧客户端 `/api/snapshot` 仍可读取当前项目）；只有输出 URL 带 token fragment 时才将其作为 Bearer 凭据，要求 HTTP 200 和有效项目列表，并核对 `currentProjectId` 对应当前项目；若显式范围不含当前目录而该值为 null，先从 projects 列表选择有效 ID 再请求 project API，不请求空 ID。项目浏览不要求先 install；若用户指定扫描范围不包含当前项目，明确说明总览需要选择项目；不擅自接入项目。仅进程启动或静态首页 HTTP 200 不足以说明数据可读。HTTP 200 仍需检查所选项目的 partial 和顶层 stale；未索引计数为 null 是正常状态。输出项目数只是此次快照，不表示所有项目或资料已读取完成。

返回大盘已打开/已启动、实际入口和停止方式（对应终端 Ctrl+C）。说明当前项目不在列表、扫描警告或宿主无浏览器等真实边界；已成功的启动不重装 CLI、不重启其它任务的服务。

服务仅监听本机，不提供远程绑定选项；保留 Host 与跨来源限制。按需开启的 token 只供当前用户本机使用，不提交到项目文档或外发。大盘只读文档，不承担自动执行、任务状态修改或云端部署。
